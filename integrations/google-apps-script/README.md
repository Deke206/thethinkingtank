# ShyneTyme Google Lead Intake

This folder contains the Google Apps Script backend used by the static ShyneTyme Works website.

## What it does

- Receives structured website form submissions.
- Creates a unique ShyneTyme lead number.
- Appends the request to a Google Sheet.
- Adds selected catalog products to a separate sheet tab.
- Emails the business inbox.
- Emails a confirmation to the customer.
- Creates a **requested**, unconfirmed Google Calendar event when a date and time were supplied.

## Required Google authorization

Google displays its own authorization dialog when `Code.gs` is first run or deployed. The script requires access to:

- **Google Sheets:** create and update lead rows in the selected spreadsheet.
- **Gmail / Mail:** send the business notification and customer confirmation.
- **Google Calendar:** create requested appointment events.
- **Google Drive:** only needed when customer photo uploads are enabled in a later step.

The authorization dialog cannot be generated by the website or committed to GitHub. It appears from Google after the owner copies this script into Apps Script and chooses **Deploy → New deployment → Web app**.

## Setup

1. Create a Google Sheet for ShyneTyme leads.
2. Copy the ID between `/d/` and `/edit` in the Sheet URL.
3. Open `Code.gs` and replace `PASTE_GOOGLE_SHEET_ID`.
4. In Google Drive, create a new Apps Script project.
5. Paste the contents of `Code.gs` into the project.
6. Run `doGet` once and approve the requested Google permissions.
7. Deploy as a Web app:
   - Execute as: **Me**
   - Who has access: **Anyone**
8. Copy the `/exec` web-app URL.
9. Replace `PASTE_APPS_SCRIPT_WEB_APP_URL_HERE` in:
   - `contact.html`
   - `build-my-auto.html`
10. Submit a test lead and verify:
    - `Leads` sheet row
    - business Gmail notification
    - customer confirmation email
    - requested Calendar event

## Safety behavior

Until a real Apps Script URL is added, the website does not send data anywhere. It saves the customer draft only in that browser's local storage and displays a setup warning.

Appointment events are labeled `[REQUESTED]` and are not treated as confirmed bookings.
